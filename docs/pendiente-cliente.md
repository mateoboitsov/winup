## 5. Cómo queréis editar la web en el día a día

Hoy el contenido vive en código (archivos de datos). Funciona bien para el lanzamiento, pero conviene decidir **cómo lo vais a mantener vosotros** después.

### Opciones que os proponemos

#### A) Nosotros editamos, vosotros pedís cambios
- **Cómo funciona:** nos escribís por email/WhatsApp con el cambio y lo subimos nosotros.
- **Pros:** cero curva de aprendizaje, cero riesgo de romper nada.
- **Contras:** dependéis de nosotros para cada cambio; puede tener coste por hora o bolsa mensual.
- **Ideal si:** cambiáis poco (1–2 veces al mes) o preferís no tocar nada técnico.

#### B) CMS visual (Sanity, Contentful o similar)
- **Cómo funciona:** panel web donde editáis textos, imágenes, proyectos y servicios sin tocar código.
- **Pros:** autonomía total, previews, historial de cambios, varios usuarios con permisos.
- **Contras:** setup inicial y coste mensual del CMS (desde ~0 € en planes free hasta ~25–99 €/mes según volumen).
- **Ideal si:** vais a actualizar proyectos, servicios o blog con frecuencia.

#### C) Notion como panel de contenido
- **Cómo funciona:** editáis en Notion (tablas para proyectos, servicios, equipo…) y la web se sincroniza automáticamente.
- **Pros:** ya conocéis Notion; muy cómodo para equipos pequeños; casi gratis.
- **Contras:** requiere configuración técnica inicial; menos flexible que un CMS dedicado para diseño fino.
- **Ideal si:** ya usáis Notion y queréis algo simple sin aprender otra herramienta.

#### D) WordPress (solo contenido) o Webflow
- **Cómo funciona:** la web actual se conecta a WordPress/Webflow para las partes editables (blog, casos, textos legales).
- **Pros:** interfaces muy conocidas; Webflow da control visual fuerte.
- **Contras:** dos sistemas que mantener; puede complicar el rendimiento y el diseño actual.
- **Ideal si:** ya tenéis experiencia con WordPress/Webflow o queréis delegar diseño a alguien no técnico.

#### E) GitHub + formación básica
- **Cómo funciona:** os enseñamos a editar los archivos de datos (textos en JSON/TS) y subir cambios con un flujo sencillo.
- **Pros:** sin coste mensual extra; control total; cambios versionados.
- **Contras:** no es visual; hay riesgo de error si se edita mal; requiere confianza con git o una app tipo GitHub Desktop.
- **Ideal si:** alguien del equipo es cómodo con tecnología y queréis máximo control sin pagar CMS.

#### F) Panel propio a medida (admin simple)
- **Cómo funciona:** construimos un `/admin` protegido con contraseña para editar proyectos, servicios, equipo y textos legales.
- **Pros:** hecho a medida para winup.; sin cuotas de terceros; interfaz mínima solo con lo que necesitáis.
- **Contras:** hay que desarrollarlo (coste inicial); mantenimiento nuestro.
- **Ideal si:** queréis autonomía pero sin depender de Sanity/WordPress y con una UI muy simple.
